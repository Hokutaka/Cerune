# コンパイル時定数

[English](constants.en.md)

**状態: 実装済み**

## 構文と用途

設定値、補正値、固定のデータをファイル間で共有します。

```cerune
const STEP: u64 = 64;
const LIMIT: u64 = STEP * 2;
fn capacity() -> u64 { return LIMIT; }
print(capacity()); // 128
```

モジュールから公開する場合は`pub const LIMIT: u64 = 128;`、参照は`settings::LIMIT`です。型は明示し、`infer`や`mut const`は使いません。宣言はファイル直下に置き、関数・通常の式・フィールドの既定値から参照できます。同じファイルの後の定数も参照できます。

| 対象 | 契約 |
| --- | --- |
| 値 | 全整数型、f32/f64、bool、string、固定長配列、構造体とその入れ子 |
| 式 | リテラル、定数参照、算術・比較・ビット演算、明示変換、短絡評価、`byte_len`、配列構築・添字、構造体構築・更新・フィールド参照 |
| 禁止 | 実行時変数の参照、通常の関数呼び出し、出力などの副作用 |
| 名前 | 代入不可。定数名と同じファイルの型・関数・別名・変数・引数との衝突を診断 |
| 公開範囲 | 既定はファイル内。`pub const`の型には非公開型を入れない。公開値の計算には非公開定数を使える |

通常の不変束縛は実行時に式を評価します。`const`はコンパイル時に評価し、その結果を使用箇所へ渡します。実行時の共有変数や初期化関数は追加しません。定数からコピーした配列や構造体を変更しても、定数と別のコピーは変わりません。文字列のUTF-8・NUL・CR/LFをそのまま保持し、正規化しません。

## 評価と診断

数値演算、変換、添字検査はVMと同じ処理を使います。整数は範囲外で失敗し、浮動小数点は型の精度で丸めます。負のゼロ・無限大・NaNも値として扱います。NaNのペイロードや物理配置は保証しません。

`false && (1 / 0 == 0)`では右辺を評価しません。ただし、型・参照・定数式としての適格性は全体を検査します。短絡される場所でも通常の関数呼び出しや循環参照は受け付けません。別の定数を参照する場合、その定数自身も検査・評価します。

未使用の定数も評価し、ゼロ除算・範囲外・不正な変換・境界外アクセスをコンパイルエラーとして報告します。プログラムの`print`は一度も実行せず、既存の出力ファイルも上書きしません。診断は定義ファイル内の失敗式を指します。通常の実行時式が定数を使って失敗した場合は、その使用箇所の診断になります。

文字列を含む定数は、値の計算後も従来の明示ターゲット要求とバイト出力の規則を保持します。

依存は宣言順に制限しませんが、循環は診断し、未評価の依存をたどる深さは128段までです。既定値を含む定数式の展開は一宣言あたり100,000ノードまでです。構造体では実際に使う既定値だけを定数として評価します。明示したフィールドや更新式で省略できる既定値を再実行しません。

## 表現と実装

1. 型と定数名を登録し、宣言全体を型検査します。
2. 定数の依存を解決し、副作用のないIRだけをVMの評価処理へ渡します。
3. Cerune IRに宣言の型・定義式・評価済みの値・Spanを残します。使用箇所は定数IDと独立したNodeId・Spanを持ちます。
4. 各生成経路には評価済みの値を渡します。実行時の加算などに戻して再評価しません。

`emit-ir`には`[compile-time]`と定義式から結果への対応、使用箇所には`const %名前@ID => 値`を表示します。bytecodeと生成物は評価済みの値を扱います。IRの対応情報を残すことと、生成先のデバッグ形式で定数名を保証することは別です。

一般の関数を実行させる「コンパイル時関数」は導入しません。停止性、副作用、使用資源の契約を別途決める必要があるためです。配列型の長さは引き続き整数リテラルで指定し、`[i64; LIMIT]`は未対応です。ブロック内の定数宣言、再export、ジェネリクスも対象外です。
