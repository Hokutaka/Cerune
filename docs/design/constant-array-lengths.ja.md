# 配列型の長さに定数を使う

[English](constant-array-lengths.en.md)

## 構文と型

```cerune
const COUNT: i64 = BASE + 1;
const BASE: i64 = 2;
fn total(values: [i64; COUNT]) -> i64 {
    mut sum: i64 = 0;
    for (value: infer in values) { sum = sum + value; }
    return sum;
}
values: [i64; 3] = [1, 2, 3];
print(total(values)); // 6
```

| 項目 | 規則 |
| --- | --- |
| 長さの書き方 | 正の整数リテラル、定数名、`alias::COUNT` |
| 定数の型 | `i8`から`u64`までの整数型。正の値で`i64::MAX`以下 |
| 計算 | 定数の定義側に書く。`[T; COUNT + 1]`や型内の関数呼び出しは未対応 |
| 型の同一性 | 確定した数値で比較。`COUNT == 3`なら`[T; COUNT]`と`[T; 3]`は同じ型 |
| 適用場所 | 変数、定数、引数、戻り値、構造体・enumのフィールド、入れ子、反復の要素型 |
| 公開範囲 | import先の定数は`pub`が必要。同じファイルの非公開定数は公開型の長さにも使える |

長さは添字変数の型を変えません。`u64`定数で長さを指定しても、添字と`array_len`の結果は`i64`です。型から値の意味が決まり、元の定数の名前や整数幅は配列型の同一性に含めません。

## 評価と依存

名前解決の後、必要な定数と型の依存をたどり、既存の定数評価器で長さを確定します。算術・変換・`byte_len`・`array_len`・配列や構造体の参照を再実装せず、VMと同じ規則を使います。前方参照と共有依存を認め、型を経由する循環も診断します。

例えば`const N: i64 = array_len(DATA); const DATA: [i64; N] = [1];`では、DATAの型を決めるためにNが必要なので循環です。配列リテラルの要素数からNを逆算しません。短絡される場所でも参照や定数式としての適格性を確認します。

長さの評価に必要な構築だけ、使う既定値を評価対象へ展開します。明示したフィールド・更新式・非選択のenum領域から、不要な既定値を実行しません。通常の関数をコンパイル時に呼びません。未使用の定数の検査・評価も従来どおり行います。

公開型に非公開の長さ定数を使えるのは、公開される型が確定済みの数値を持つためです。別モジュールから非公開の定数名へアクセスする権限は増えず、非公開の要素型を公開することもできません。

## 診断・資源・観測

- 0・負数・非整数・範囲外の長さは型中の参照位置で診断します。定数の計算に失敗した場合は定義内の失敗式を指します。
- 型と定数をたどる未解決の依存は128段まで。長さ用の定数式展開は一宣言10万ノード、式の深さ128までです。
- 一つの複合値の型は展開後10万scalar分、型計算の深さ128までです。配列は長さとの積、構造体はフィールドの和、enumはタグと全選択肢の格納領域で数えます。空の構造体は1と数えます。
- 上限は定数名・リテラル・`infer`で共通です。これはコンパイラの資源上限であり、実際のバイト数や全プログラムのメモリ上限ではありません。文字列は内容のバイト数によらず一つのscalar分です。
- コンパイル失敗では実行文へ進まず、既存の出力ファイルを上書きしません。実行時の範囲外アクセスは長さの定義ではなく、そのアクセス位置を指します。

元のASTには定数名とSpanを残し、生成用の型は数値の長さへ解決します。Cerune IRは定数の定義式・結果に加え、`array-length %COUNT@ID => 3 [source=… bytes=…]`で型中の参照位置を示します。長さは実行時に再計算せず、既存の固定長配列として全経路へ渡します。観測情報は、定数や実行中の配列を書き換える窓口ではありません。
