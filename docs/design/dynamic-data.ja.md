# 動的データ：文字列の所有と寿命

[English](dynamic-data.en.md)

**文字列連結は実装済みです。動的配列・借用スライスは設計段階です。** IR Executor・VM・C・LLVM・QBE・WAT・Windows/Linux ASM・自前COFF/ELFで同じ値の意味と所有の展開を使います。

## 文字列連結

`concat(left, right) -> string`は二つの`string`だけを受け取る組み込み操作です。暗黙の数値文字列化や`+`の意味変更はありません。

1. 左、右の順で一度ずつ評価する。左が停止したら右は評価しない。
2. 長さの和、生成先の配置サイズ、動的文字列の予算を検査する。
3. 新しい領域へ左の全バイト、右の全バイトをコピーする。
4. 結果を不変な文字列として渡し、一時値を解放する。

日本語・NUL・CR/LF・結合文字をそのまま保持し、正規化・改行変換・終端NULの追加はしません。比較、`byte_len`、単独表示、複合値内の引用表示は既存どおりです。合計0バイトなら静的な空文字列を使い、それ以外は空文字列との連結でも一つの領域を確保します。引数の評価は省略しません。

`const`では同じ規則で評価した結果を静的な文字列へ保存します。元の初期化式と結果はIRに残し、実行時の所有領域をコンパイル結果へ持ち越しません。

## コピーと寿命

| 対象・場面 | 処理 |
| --- | --- |
| 静的文字列 | 保存領域を共有し、保持・解放は作用しない |
| 動的文字列 | 不変の内容を共有し、論理的な参照数を保持・解放する |
| 配列・構造体 | 独立した値をコピーする。文字列フィールドの不変内容は共有できる |
| enum | 選択中のペイロードだけを保持・解放する |
| 再代入 | 右辺を完全に評価してから旧値を解放し、新しい値を保存する |
| 関数の返却 | 戻り値の所有を確保してから局所値と引数を解放する |
| ブロック終了・return・break・continue | 対象の束縛を定義した逆順に解放する |
| ループの条件・更新・短絡 | 元の評価位置で一時値を生成・解放する |

`s = concat(s, suffix)`や`s = s`は有効です。別の変数に保存した内容は再代入で変わりません。利用者が呼ぶ`free`、暗黙のmove、ポインタ型、GC、共有可変参照は導入しません。観測から所有情報を書き換えるAPIも公開しません。

IR ExecutorとVMでは成功時の局所値を解放し、失敗時も呼び出しの終了境界で残った内容を回収してからホストへ戻します。既存の埋め込みAPIの外部値型は広げません。ネイティブの異常停止はプロセス単位で、残った領域はOSが回収します。WATでは成功した呼び出しの領域を再利用でき、失敗したインスタンスは破棄して再利用しません。

## 予算と失敗

既定の予算は**生存している動的文字列の内容64 MiB（67108864バイト）**です。共有領域は一度だけ数え、静的リテラルは除きます。再代入中に旧値と新値が共存すれば両方数えます。

`run`・`run-ir`・`run-vm`とコード生成コマンドに`--string-heap-limit <bytes>`を渡して変更できます。0も有効です。コンパイル時評価は独立した64 MiBの上限を持ち、このオプションでは変更しません。Rust APIでは生成・bytecode化の前に`ir::Program::string_heap_limit`を設定します。実行中の状態へ介入する設定ではありません。

```sh
cerune run examples/string_concat.ceru --string-heap-limit 1024
cerune emit-c examples/string_concat.ceru --string-heap-limit 1024 -o concat.c
```

| 停止コード | 原因 |
| --- | --- |
| `allocation-size-overflow` | 長さの和または配置サイズを表現できない |
| `allocation-limit-exceeded` | 生存内容の合計が明示予算を超える |
| `allocation-failed` | 検査後の確保が失敗する。WATでは利用可能な線形アドレス空間の不足も含む |

論理的なバイト長は`i64`です。ヘッダーと配置サイズを検査し、wasm32では検査前に上位ビットを切り捨てません。失敗時は元の連結式のNodeId・Spanと[共通の停止記録](runtime-diagnostics.ja.md)を残します。先行出力を維持し、後続の式は実行しません。

予算は物理メモリ全体の上限ではありません。管理情報・スタック・断片化・ホストの都合で、予算内でも確保に失敗し得ます。予期しないOSの強制終了やアクセス違反を`allocation-failed`の正常な診断には扱いません。

## 生成過程と保存形式

共通IRの`string.concat.allocate-copy`が、検査・確保・左右のコピーを要求します。`ownership-expression`・`ownership-replace`などの生成関数と、`string.retain`・`string.release`で順序と寿命を表します。配列の走査、構造体フィールド、enumのタグ分岐も通常のIRに展開します。元の式のSpanを保持し、追加の文・式には一意なNodeIdを付けます。

各backend IRと成果物には、サイズ計算・予算検査・確保の呼び出し・コピー・解放が残ります。`emit-ir`と`emit-bytecode`は実行時予算も表示します。LLVM・ASM・objectでは既存の出自注釈を利用できます。格納形式や実行時アドレスが経路間で同じである必要はありません。

| 経路 | 動的領域の実装 |
| --- | --- |
| IR Executor / VM | 内容の共有ハンドルと論理的な参照数を分離。最後の解放で内容を回収し、失敗時は呼び出し単位で回収 |
| C / LLVM | 既存のデータ参照＋長さを維持。動的領域だけをリストで識別し、`malloc` / `free`で管理 |
| QBE / ASM / 自前object | 既存の長さヘッダーへの参照を維持。動的ヘッダー・参照数・リストを管理 |
| WAT | 非公開memoryの空きブロックを再利用。必要時だけ`memory.grow`し、失敗を検査 |

ネイティブの動的ヘッダーはリンク・参照数・長さ、WATはリンク・参照数・容量・長さを持ちます。静的文字列の直前をヘッダーと仮定して読みません。リスト探索を使う初回実装なので、保持・解放の時間は登録領域数に依存します。WATは先に見つかった十分な空きブロックを再利用し、分割・結合・縮小はまだ行いません。解放済みブロックの容量は生存予算に含めません。

LLVMのOSを実行中の環境から決めず、明示ターゲットを使います。自前COFF/ELFは管理情報を非実行の書き込み可能`.data`節へ置き、静的文字列は読み取り専用のままです。WATのmemoryはexport/importしません。外部ツールの起動とリンクは生成物を受け取る側の責務です。

## 検証例

[string_concat.ceru](../../examples/string_concat.ceru)で連結・返却・再代入・配列コピー・バイト保持・ループを確認できます。共通の`concat_cases`では既定値・enum・matchガード・型引数・定数・左右の副作用・自己代入・早期returnも照合します。

`string_heap_routes`は同じ小さい予算を全経路へ渡し、既知の出力、予算超過、先行出力、元の位置、添字検査の順序を比較します。WATはmemoryを1ページに制限した内部テストで領域再利用を確かめ、同じインスタンスの成功した呼び出しを繰り返します。CはASan/UBSanでも検証します。確保失敗を返す固定条件とサイズ超過は内部テストで区別します。

## 次：動的配列と借用スライス（未実装）

所有する動的配列と範囲コピーを先行し、借用スライスはその後に設計します。[動的配列の仕様案](owned-arrays.ja.md)に、コピーの時点、読み取りとの区別、共通の予算計算、停止順序と全経路の完了条件をまとめています。以下の候補を具体化した案で、まだ実装済みの仕様ではありません。

- 動的配列の型候補は`[T]`。`[T; N]`と区別し、長さ0と`0 <= length <= capacity`を認める。容量は要素数で、初回は必要量だけ確保する。
- コピーは入れ子の可変領域も独立させる。文字列内容の不変共有は可能。要素型に沿うコピー・解放を共通IRへ展開し、サイズの積・和を検査する。
- `array_copy_range(values, start, end)`は対象・開始・終了を左から一度ずつ評価し、`0 <= start <= end <= length`を検査する案。半開区間`[start, end)`を独立した所有値へコピーし、末尾の空範囲も許す。
- 参照・更新・引数・返却・比較・表示・反復を一組で設計する。固定長配列からの変換も明示する。予約容量や成長率は後続の操作とする。
- 借用では所有者の寿命・更新・再確保の型規則を先に定義する。所有者を失う返却や借用中の変更を許すかを曖昧にしない。文字列のバイト範囲とUTF-8の文字境界は混同しない。

[bounded_sequence.ceru](../../examples/bounded_sequence.ceru)と[array_window.ceru](../../examples/array_window.ceru)は固定容量での基準例です。`append`・`copy_range`はそこで定義した関数で、動的配列の組み込み操作ではありません。使用数の整合性は例の関数が検査し、未使用領域も固定長値の一部です。再帰・外部入出力は、呼び出し領域・資源上限・失敗・終了処理を別途決めます。
