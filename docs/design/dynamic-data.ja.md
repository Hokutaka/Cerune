# 動的データ：所有・寿命と生成過程の提案

[English](dynamic-data.en.md)

**状態: 設計提案・未実装。** 文字列連結・動的配列・借用スライスは現在の言語機能ではありません。ここでは実装の順序と受入条件を決めます。構文・CLIオプション・IR命令名の候補は、言語リファレンスの現行仕様と区別します。

## 最初に何を作るか

**文字列連結 → 所有する動的配列と範囲コピー → 借用スライス**の順を推奨します。文字列連結なら既存の`string`で、実行時の確保、関数からの返却、再代入、解放を一通り検証できます。借用から始めると、コピーに加えて所有者の寿命と更新の制約を同時に導入する必要があります。

| 段階 | 利用者にできること | 先に確認すること |
| --- | --- | --- |
| 1. 文字列連結 | 二つの文字列から新しい文字列を作り、返却・配列格納・再代入する | バイト保持、保持・解放、確保失敗、短絡と出自 |
| 2. 所有する動的配列 | 実行時の要素数、空配列、要素更新、独立した範囲コピー | 要素型ごとのコピーと解放、長さ・容量、積と和のサイズ検査 |
| 3. 借用スライス | 所有者の一部をコピーせず読む | 所有者より長生きしないこと、借用中の更新・再確保の制約 |
| 後続 | 再帰・外部入出力 | 呼び出し領域と資源上限、入出力失敗と資源の終了処理 |

初回に新しいポインタ型、利用者が呼ぶ`free`、暗黙のmove、GC、外部から値を書き換える観測APIは追加しません。名前付き型のジェネリクスは別の機能です。

## 現在から変わる点

[文字列](strings.ja.md)は現在、VMではRustの`String`をコピーし、生成先では静的なデータを参照します。[固定長配列](fixed-arrays.ja.md)は大きさが型で決まり、独立した値としてコピーします。WATのlinear memoryも現在は生成時に必要量を決めます。

動的データには「どこに置くか」だけでなく、「誰が使用を終えるか」が必要です。Cだけの`malloc`追加で完了とはせず、共通IRで意味を決め、各経路の寿命と資源処理を検証します。格納形式・ポインタ幅・命令列が同じである必要はありません。

## 所有とコピーの基本案

| 対象 | コピーの意味 | 最初の実装方針 |
| --- | --- | --- |
| 数値・bool・既存の固定長値 | 既存どおり独立した値 | 既存のコピー |
| 静的文字列 | 不変な同じ内容 | 保存領域を共有し、実行中は解放しない |
| 動的文字列 | 不変な同じ内容 | 不変バイト領域を参照カウントで保持し、最後の使用後に解放 |
| 動的配列 | コピー後の更新が元へ波及しない | 独立した要素領域を確保し、要素を型に従ってコピー |
| 借用スライス | 所有者の領域を見る | 別の型・別の寿命規則として後から設計 |

文字列の共有は、その内容を変更する操作がないことを根拠にします。`mut`な文字列変数の再代入は、その変数の値の置き換えです。動的配列のコピー時に文字列要素の領域を共有しても、配列の要素を別の文字列へ置き換える操作は元の配列へ伝わりません。

すべての文字列コピーでバイトを複製する案も単純ですが、受け渡しのたびに確保が必要になります。実行終了まで全領域を残す案では、ループ内の再代入が使わなくなった領域を蓄積します。初回は、不変文字列だけを参照カウントで管理し、保持と解放の位置をIRに残す方針を推奨します。共有可変配列やcopy-on-writeは採用しません。

## 最初の文字列連結

呼び出し名の候補は`concat(left, right)`です。新しい構文としてはまだ使えません。二つの`string`だけを受け取り、`string`を返す案とします。暗黙の数値文字列化や`+`の意味変更は行いません。

1. 左、右の順で一度ずつ評価する。左が停止したら右は評価しない。
2. 両方のバイト数の和、配置に必要な大きさ、明示した資源上限を検査する。
3. 結果領域を確保し、左の全バイト、右の全バイトを順にコピーする。
4. 内容を不変として確定し、結果の所有権を返す。後続処理と一時値の解放位置をIRに残す。

日本語、NUL、CR/LF、結合文字をそのまま連結します。正規化・改行変換・終端NULの追加はしません。比較、`byte_len`、単独表示、複合値内の引用表示は既存の意味を保ちます。

最初の実装では、合計が0なら静的な空文字列を使い、それ以外は空文字列との連結でも結果領域を一つ作る案です。両方の引数の評価は省きません。確保を省く最適化は、観測との対応、資源上限、失敗条件まで検証した別の変更として扱います。

定数式は同じ連結規則でコンパイル時に評価し、結果を静的な文字列へ保存する案です。元の式と評価結果をIRへ残し、コンパイル時のバイト上限も明示します。実行時の所有領域をコンパイル結果に持ち越しません。

## 寿命・再代入・終了

- 束縛・引数・戻り値に動的文字列を保存するときは、必要な所有の保持を生成する。静的データは保持・解放の対象外とする。
- 再代入は右辺を完全に評価してから値を置き換え、古い値を解放する。`s = concat(s, suffix)`の途中で`s`を解放しない。
- 戻り値が局所変数と同じ領域を参照していても、返却先へ所有を渡してから局所値を解放する。
- ブロック終了、`return`、`break`、`continue`、ループの条件・更新で、一時値と束縛を定義した順の逆順に解放する。複合値は型に沿って所有する部分を処理し、enumは選択中のペイロードだけを処理する。
- 失敗した構築の途中に確保済み領域があれば、その実行の終了境界で回収する。言語の任意のデストラクタは呼ばない。

VM埋め込みでは呼び出しが失敗しても、内部に残った動的領域を回収してからホストへ戻します。現在の埋め込みAPIの値型を、この変更だけで勝手に広げません。ネイティブ実行がプロセスごと停止する場合はOSの回収が終了境界です。WATのtrapでは後続の解放命令を実行できないため、初回の契約は失敗したインスタンスを破棄し、再利用しない形を推奨します。成功した呼び出しでは一時領域を回収し、繰り返し実行でも蓄積させません。

実装上の参照カウントと所有情報をソースから変更するAPIは公開しません。正常終了時の解放や異常終了時の回収は実行契約であり、観測からの介入ではありません。

## 上限と失敗

長さの論理型は既存の`byte_len`・添字と同じ`i64`を基本とします。保存先のアドレス幅へ変換する前に検査し、wasm32で上位ビットを切り捨てません。ヘッダー、アラインメント、要素数とstrideの積もチェックします。

| 原因 | 診断の候補 | 出自 |
| --- | --- | --- |
| 長さの和・配置サイズが表現可能範囲を超える | `allocation-size-overflow` | 連結・確保・コピーの元の式 |
| 明示した動的データ予算を超える | `allocation-limit-exceeded` | 同上 |
| 検査後に対象の確保処理が失敗を返す | `allocation-failed` | 同上 |

これらのコードはまだ実装されていません。導入時は[共通の停止記録](runtime-diagnostics.ja.md)、reader、VM・全生成先を同時に更新します。予期しないアクセス違反やOSによる強制終了を、確保失敗の正常な診断として扱いません。先行出力は維持し、後続の式は実行しません。

初回の予算案は**生存している動的文字列の内容64 MiB**です。同じ不変領域の共有は一度だけ数え、静的リテラルは含めません。再代入中に旧値と新値が共存する分は両方数えます。コンパイル時評価にも独立した同量の上限を設ける案です。実装前に、この既定値と明示的な変更方法を確定します。現在のCLIにその設定はありません。

予算は物理メモリ全体の上限ではありません。管理情報、スタック、生成物、ホストの都合で必要量は増え、予算内でも実際の確保が失敗し得ます。実際のOSの空きメモリまで経路間で同一とは仮定しません。全経路の失敗比較には小さな明示予算を使い、外部から実行中のアロケータを書き換える仕掛けを観測APIとして追加しません。

## 動的配列とスライスの境界

所有する動的配列の型表記は`[T]`を候補とし、`[T; N]`とは区別します。長さ0を認め、`0 <= length <= capacity`を満たす値を内部で構築します。容量は要素数と区別し、初回は結果に必要な長さだけ確保する案です。成長率や予約容量は後続の明示操作として検討します。

要素の参照・更新、関数や複合値での受け渡し、比較・表示・反復を一組として設計します。配列コピーは入れ子の可変な領域も独立させ、文字列は上記の不変共有を使います。型ごとのコピーと解放を共通IRへ展開します。固定長配列から動的配列への変換は明示操作とし、暗黙には行いません。

範囲コピーの候補は`copy_range(values, start, end)`です。対象・開始・終了を左から一度ずつ評価してから、`0 <= start <= end <= length`を検査します。範囲は終端を含まない`[start, end)`で、末尾の空範囲も認めます。結果は独立した所有値です。借用スライスと呼び分け、コピー量・確保をIRに示します。

借用スライスは別の検討です。「読み取り専用」とするだけでは、元の配列の変更・再確保・寿命切れを防げません。所有者を失う返却、所有者を変更する呼び出し、借用中の更新をどう型検査するか決めるまで実装しません。文字列のバイト範囲と文字境界も配列スライスへ混ぜず、UTF-8を壊す文字列操作を暗黙には作りません。

## 生成過程で必ず見せるもの

次は概念上の流れで、現在のIR命令の綴りではありません。

```text
ソースの連結
  → 型付きIR: concat(left, right), NodeId, Span
  → 所有の展開: 評価 → 長さ検査 → 予算検査 → 確保 → バイトコピー → 結果
                保持・解放・正常終了／失敗時の回収境界
  → backend IR: 配置・アドレス幅・呼出規約・実際の検査とループ
  → bytecode / C / LLVM / QBE / WAT / ASM / object
```

元の操作と展開後の処理を対応付け、合成した処理には役割と生成理由を付けます。確保のバイト数、静的／動的の区別、所有の保持、最後の解放が分かるようにします。最適化で省いた処理も、その根拠を追える形にします。ポインタ値や実行時IDを経路間で一致させることは求めません。

| 経路 | 実装時に必要な変更 |
| --- | --- |
| VM | 動的領域の管理、fallibleな確保、呼び出し終了時の回収 |
| C / LLVM | 静的文字列と動的文字列を区別する内部表現、保持・解放、明示ターゲットに対応するruntime |
| QBE / ASM / 自前object | 同じ所有の展開を命令と再配置へ落とす。確保関数をリンクする契約も記録 |
| WAT | 非公開memory内の管理領域、再利用可能な確保・解放、メモリ拡張失敗の検査、trap後のインスタンス契約 |

CやOSのアロケータにCeruneの値の意味を決めさせません。WATでは確保のためにmemoryをexport/importして外部から書き換える契約を追加しません。外部ツールの起動・リンクは引き続き成果物を受け取る側の責務です。

| example | 現在の機能で確かめること | まだ確かめられないこと |

| [array_window.ceru](../../examples/array_window.ceru) | 半開範囲、空範囲、不正範囲、評価順、短絡、元を変更した後のコピー | 実行時に容量を確保する配列・借用 |
| [string_values.ceru](../../examples/string_values.ceru) / [aggregate_display.ceru](../../examples/aggregate_display.ceru) | 文字列の不変性とバイト、入れ子の表示 | 実行時の連結・動的領域の寿命 |

最初の二つは通常の型・関数で書いた**固定容量の例**です。`copy_range`・`append`も例のユーザー定義関数で、組み込み機能の追加ではありません。未使用領域も固定長配列の一部なので、構造体全体の表示には現れます。使用数の整合性は例の関数が検査し、型そのものが自動で保証するわけではありません。

```sh
cargo run --quiet -- run examples/bounded_sequence.ceru
cargo run --quiet -- run examples/array_window.ceru
cargo run --quiet -- emit-ir examples/array_window.ceru
cargo run --quiet -- emit-llvm examples/array_window.ceru --target x86_64-unknown-linux-gnu --annotate-origins
```

共通の期待出力をVM・C/LLVM・QBE・WAT・Windows/Linux ASM・自前COFF/ELFで比較します。これらは今後の設計の基準であり、未実装のヒープ管理を検証したとは扱いません。

## 次の実装PRの完了条件

1. 連結の名前・呼び出し規則、予算の既定値と設定方法、文字列表現と所有の展開を確定する。
2. 空・日本語・NUL・CR/LF・非正規化文字列を連結し、返却・再代入・入れ子の配列・enum・定数で比較する。
3. 左右の副作用と停止、短絡、旧値を使う再代入、早期return・break・continueの寿命を検査する。
4. 小さい予算で失敗を再現し、確保サイズ超過・予算超過・実際の確保失敗を区別する。確保処理の失敗を返すテストは内部検証用の固定した入力条件で行う。
5. ループで保持・解放が釣り合うこと、終了後に生存領域が残らないことを検査し、CではASan/UBSanも使う。
6. 全経路の既知出力・停止理由・元の位置・先行出力、通常／注釈付きの生成物を比較し、exampleと日英仕様を更新する。
