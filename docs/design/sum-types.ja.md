# 直和型と網羅的な分岐

[English](sum-types.en.md)

**状態: 実装済み**

## 用途と構文

「見つかった値」と「未登録」を一つの型にまとめます。成功・失敗を返す場合も、成功値と失敗理由を別の選択肢にできます。

```cerune
enum Lookup { Found { text: string }, Missing, }
fn lookup(key: string) -> Lookup {
    if key == "sky" { return Lookup::Found { text: "空" }; }
    return Lookup::Missing {};
}
match lookup("sky") {
    Lookup::Found { text: value } => { print(value); },
    Lookup::Missing {} => { print("未登録"); },
}
```

| 項目 | 契約 |
| --- | --- |
| 型 | `enum`は名前で区別する値型。選択肢は一つ以上 |
| 値 | `Enum::Variant { field: value }`。値を持たない選択肢も`{}`を付ける |
| ペイロード | 明示型付きの名前付きフィールド。数値・bool・string・配列・構造体・直和型を保持 |
| 分岐 | `match`は文。全選択肢を各一回書き、各フィールドを束縛するか`field: _`で捨てる |
| 束縛 | 分岐内だけで使える不変のコピー。元の値への参照ではない |
| 受け渡し | 変数・引数・戻り値・配列・構造体・定数で使用可能 |
| モジュール | `pub enum`で全選択肢とフィールドを公開。外部から`alias::Enum::Variant`で利用 |

構築時はフィールドをソース順に一度ずつ評価します。既定値はenumのフィールドには書けません。ペイロードに構造体を明示して作る場合は、その構造体の通常の既定値規則が適用されます。

`match`の対象は一度だけ評価してコピーし、選んだ分岐だけ実行します。分岐中に元のmut変数へ別の選択肢を代入しても、取り出した値は変わりません。`return`は関数へ、`break`・`continue`は囲むループへ作用します。全分岐が必ず戻る`match`は、関数の戻り値検査でも考慮します。

対象へ構築式を直接書くときは`match (Lookup::Missing {}) { ... }`のように括弧を付けます。配列や構造体の既存の条件式と同じ、ブロックとの曖昧さを避ける規則です。

## 検査と失敗

不足・重複した選択肢、異なるenumの混在、対象とパターンの型不一致、フィールドの不足・重複・型不一致をコンパイル時に診断します。公開enumのフィールドに非公開型を含められません。循環する値型も無限の大きさになるため拒否します。

回復可能な失敗は、プログラム自身が`Error { ... }`などの値を返して扱います。整数の桁あふれ・ゼロ除算等の実行時停止を捕捉する機能ではありません。対象やペイロードの評価で停止したら後続の評価を行わず、既存の停止理由・式のSpan・先行出力を保ちます。

全体の`print`・等値比較、直接フィールド参照、enumに対する構造体更新式は未対応です。値は`match`で取り出して利用します。ガード、全体ワイルドカード、入れ子パターン、match式、暗黙のエラー伝播、ジェネリクスや組み込みOption/Resultも導入していません。

## 共通の表現と観測

モジュールの名前解決後、共通フロントエンドがenumをタグ付きの構造体へ展開します。全経路はその同じ型付きIRを受け取ります。

- `emit-ir`は`enum %Lookup@0 tags [Found=0, Missing=1]`のように選択肢とタグの対応を表示します。
- 内部の`$tag`と`$Found$text`等の領域、対象コピー、タグ比較、分岐をIRに残します。`$`はソースの識別子に使えないので、利用者の名前と衝突しません。
- タグと非選択領域の初期値はIRとbytecodeで`[generated]`／`generated`と示し、ソースの明示値・既定値と区別します。評価済みの定数から再構成するフィールドも合成値として示します。
- 型・フィールド、構築時の値、対象式、パターンの束縛、分岐内の演算にはソース位置が残ります。合成した比較には該当パターンの位置を使います。外部からタグや値を書き換えるAPIは提供しません。
- 最初の配置は`i64`のタグと**全選択肢のペイロードの合計**です。領域を重ねるunionではありません。動的確保は導入せず、配置・タグ値は安定ABIとして約束しません。
- 非選択の領域は型に沿ったゼロ値で初期化します。利用者の既定値・関数を実行しません。内部値は言語のパターンから取り出せません。初期化展開は一構築あたり100,000ノードまでとし、名前付き型の探索深さが128に達すると診断します。

領域を重ねる最適化は、コピー・寿命・生成先の配置・観測の対応を検証した後の候補です。現在は全経路で同じ値の意味を保つ、追跡しやすい表現を採用しています。
